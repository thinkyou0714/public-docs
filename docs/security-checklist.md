# 機密混入防止チェックリスト（Security Checklist）

## 原則

> `sanitized` / `publish` / `public docs` / `NotebookLM投入ファイル` には
> **一切の機密情報を含めない**。

## 禁止項目一覧

| カテゴリ | 具体例 | 検出パターン |
|---------|--------|------------|
| URL | 社内ツール、管理画面、API endpoint | `https?://`, `http://` |
| 企業名/個人名 | 顧客名、担当者名、社名 | 手動確認（自動化困難） |
| 数値 | 売上、件数、KPI、単価 | 手動確認（文脈依存） |
| 内部リンク | 社内Wiki、Slack、Notion | `notion.so`, `slack.com` 等 |
| トークン/キー | APIキー、アクセストークン | `sk-`, `xoxb-`, `Bearer`, 長いランダム文字列 |
| Webhook URL | 自動化ツールのエンドポイント | 固有ドメインのURL |
| パスワード | 認証情報 | `password`, `passwd`, `secret` |
| メールアドレス | 個人・業務アドレス | `@` + ドメイン |
| IPアドレス | サーバーIP | `\d+\.\d+\.\d+\.\d+` |

## 自動チェック: check-secrets.sh

```bash
npm run check-secrets
# または
node scripts/check-secrets.mjs
```

### チェック対象

- `content/**/*.mdx` — 公開用コンテンツ
- `obsidian-templates/**/*.md` — Obsidianテンプレート

### チェック内容

1. URL検出（`https?://` パターン）
2. トークンパターン検出（`sk-`, `xoxb-`, `xoxp-`, `Bearer`, `token`）
3. IPアドレスパターン検出
4. メールアドレスパターン検出
5. 一般的なシークレットキーワード検出

### 注意事項

- 自動チェックは **補助** であり、完全ではない
- 企業名・個人名・数値は文脈依存のため手動チェック必須
- 新しいパターンを発見したら `scripts/check-secrets.mjs` に追加

## 手動チェック手順

1. 記事の全テキストを通読
2. 以下を確認:
   - [ ] URLが1つも含まれていないこと
   - [ ] 企業名/個人名（実名）が含まれていないこと
   - [ ] 具体的な数値（売上、件数等）が含まれていないこと
   - [ ] 内部ツールへのリンクが含まれていないこと
   - [ ] トークン/APIキー/パスワードが含まれていないこと
   - [ ] Webhook URLが含まれていないこと
   - [ ] メールアドレスが含まれていないこと
   - [ ] IPアドレスが含まれていないこと
3. 不明な箇所は `#secret_suspected` タグを付けて保留

## Obsidian運用との連携

| フォルダ | 機密 | 数値 | NotebookLM | 顧客送付 |
|---------|------|------|-----------|---------|
| `/00_raw_private` | OK | OK | **禁止** | **禁止** |
| `/10_sanitized` | **禁止** | **禁止** | OK | OK |
| `/20_publish` | **禁止** | **禁止** | OK | **禁止**（サイト公開用） |

## インシデント対応

1. 機密が公開リポジトリに混入した場合:
   - 即座に該当コミットをrevert
   - 混入した機密情報を無効化（トークンの場合はリボーク）
   - 変更履歴に「機密混入→sanitize」を記録
2. NotebookLMに `raw_private` を投入した場合:
   - 該当ノートブックを削除
   - 投入した情報の機密レベルを評価
   - 必要に応じて関係者に報告
